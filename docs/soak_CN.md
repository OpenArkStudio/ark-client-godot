# 有界本机多进程持续验收

先启动专用、空大厅的访客房间服务端，再使用 .NET 8 执行：

```sh
DOTNET=/path/to/dotnet bash tools/soak-three-clients.sh 127.0.0.1 19100 600
```

默认持续 600 秒，接受 30–3600 秒。脚本串行构建永久 C# 测试程序，再启动三个独立
便携客户端进程。Alice 和 Bob 在完整时段内保持连接；Churn 约每五秒退房重连，
比常驻客户端提前五秒结束，让双方确认最后一次删除。起跑屏障要求三方均入房后才
开始计时。服务端应由操作者拥有；此脚本不启动或停止服务端。

每个客户端约每 250 ms 请求一次移动、动作和心跳。每轮最多等待八秒，核对匹配的
移动序列号及位置、动作序列号及 HP／MP、心跳 nonce。动作循环为受伤、技能、恢复、
封顶恢复。重连核对新的玩家及 Entity ID、唯一完整基线和重置属性。常驻客户端在
其他玩家移动、动作、加入和删除期间持续验证协议副本。最后的跨进程检查要求两个
常驻客户端均观察到每条 churn 连接及其删除。任意错误都判失败，不重试或重放活动。

输出的临时目录保存各进程日志、JSON 计数、退出码、PID，以及每秒一次的 `ps` CPU
百分比、RSS（KiB）和累计 CPU 时间。CPU 范围为单个进程，100% 表示占用一个逻辑核。
采样包含进程启动阶段，不测量整机 CPU 或精确内存分配保留情况。原始测量应留在
版本控制之外。另行记录服务端 CPU／RSS、精确源码及二进制哈希，正常停止自有服务端，
再确认监听端口退出。

这是三个便携 C# 客户端的有界功能与资源观察工作负载，不执行 Godot 场景或导出包，
不验证跨主机网络，不解释已延期的 TCP 5000 问题，也不代表生产 PCU 容量。
其他检查见[验证记录](validation_CN.md)。
