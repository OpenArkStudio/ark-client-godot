Godot `4.7.2.stable.mono.official.ed1daf0bf`，本地 .NET SDK `10.0.403`、
.NET 运行时 `8.0.33`。项目目标为 `net8.0`，客户端托管检查使用 SDK `8.0.427`。
常规 .NET 8 SDK 已包含所需运行时与引用包。

| Godot 构建、导入与离线运行 | 通过，构建无警告和错误，输出明确的 ARK2 C# 就绪标记 |

| 原生导出 → JSON → Kernel → Godot | C++ 工具导出字段表与配置，两次服务端启动均加载该 JSON，并完成持续运行与重启验证 |
| 持续连接与反复入房 | 两个 Godot 进程持续连接 300 秒；每 30 秒增加一组双客户端，完成共 10 组入房、动作、移动与重入，最多同时 4 个客户端 |

| 客户端托管检查 | [运行 40452878174](https://github.com/OpenArkStudio/ark-client-godot/actions/runs/40452878174)在上述运行时代码上通过三平台检查；Linux 另行构建、导入并离线运行 Godot 场景 |
| 场景渲染 | 引擎在真实双客户端检查中导出自身视口，已查看村庄、YOU/PLAYER 标记、实际 HP/MP 条和动作按钮；未将新增按钮的人工点击算作通过 |
| 本机人工体验 | 2026-10-27，维护者在服务端与两个可见 Godot 客户端中体验移动同步、HP/MP 变化及断线重连后反馈无异常；此项是人工确认，与上述自动化结果分别记录 |

服务端采用真实 ark 启动器及 Net、Bus、Utility、Kernel 和房间插件，未使用替代 TCP 服务。
每组引擎检查都要求先观察到自己和对方的中间属性状态，再重新连接；仅看到最终 100/100 不算通过。
新连接加载 100 HP/MP、动作序号 0，且不保留或重放待确认动作。

[房间预览](images/room.png)直接采用该功能检查中的引擎渲染帧，未修改图像。
录制会增加开销，画面中的 RTT 不作为性能测试数据。这次渲染检查未使用桌面截图或人工输入。

服务端使用 JSON 实体字段和业务配置；现有插件启动配置外壳仍为 XML。
数据模型及永久保存的编译、引擎检查入口见[数据同步](data-sync_CN.md)和[运行说明](run_CN.md)。

## 证据边界

这些结果证明本机有限时长内的功能连续性与故障恢复，不代表性能、无内存泄漏、生产容量、
跨主机网络或桌面导出包验收。服务进程重启后建立新会话，数字 ID 可能复用，不恢复账号或先前状态。
认证和持久化不在本演示范围内。托管离线检查不会启动 ark 服务端，原始日志与测量回执仅保存在本机。
