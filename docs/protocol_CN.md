# 访客房间协议 v1

本示例显式选择独立的 ark 消息头，保留已有 ark 原生 CS 与 SS 消息头。
传输使用原始 TCP，不叠加 Godot 多人游戏或 ENet 帧格式。
客户端与配套服务端共享 [`tests/fixtures/wire-vectors.json`](../tests/fixtures/wire-vectors.json)。

| 偏移量 | 字节数 | 内容 |
| --- | --- | --- |
| 0 | 4 | ASCII `ARK1`，包含协议版本 |
| 4 | 2 | 消息 ID，无符号大端整数 |
| 6 | 2 | 标志，无符号大端整数，必须为零 |
| 8 | 4 | 正文字节数，无符号大端整数，不包含消息头，最多 4096 |

正文为 UTF-8 JSON 对象。无效标记、非零标志和过大长度在业务分发前导致连接关闭。
空正文向量仅验证帧编解码；空正文不属于有效的房间 JSON 消息。
接收端保留不完整消息帧，解析合并到达的多个消息帧，并在重连时清空缓冲区。

| ID | 方向 | 正文 |
| --- | --- | --- |
| 60000 | 客户端 → 服务端 | `{"name":"Alice","room":"lobby"}` |
| 60001 | 服务端 → 新成员 | `{"player_id":"1","name":"Alice","room":"lobby","width":960,"height":540}` |
| 60002 | 客户端 → 服务端 | `{"seq":1,"x":120,"y":100}` |
| 60003 | 服务端 → 已加入成员 | `{"room":"lobby","players":[{"id":"1","name":"Alice","x":120,"y":100,"seq":1}]}` |
| 60004 | 服务端 → 客户端 | `{"code":"invalid_message","message":"reason"}` |
| 60005 | 客户端 → 服务端 | `{"nonce":1}` |
| 60006 | 服务端 → 客户端 | `{"nonce":1}` |

唯一房间为 `lobby`，最多容纳 16 名玩家。名字非空，最多包含 64 个 UTF-8 编码字节，
且不含控制字符。序列号和 nonce 为无符号 32 位整数。
移动序列号从 1 开始严格递增。坐标必须为有限值，分别位于 `0..960` 和 `0..540`。
初始位置由服务端决定。成功加入时先返回接受消息，再发送完整快照；
接受移动或成员断线后，服务端向房间成员广播更新后的快照。

玩家 ID 是服务端进程内的不透明字符串。重新加入时创建新 ID 并获取完整快照；
客户端清空旧成员列表、移动序列号及未完成消息帧。
错误码包括 `room_full`、`already_joined`、`not_joined`、`invalid_message` 和 `stale_sequence`。
无效业务请求不改变房间状态。界面显示服务端错误；加入被拒绝后需手动重试。

客户端每秒最多发送 10 次移动。传输层最多保留 64 个接收事件、
一个不完整的 4108 字节消息帧，以及一个待完成的发送操作。
连接与发送操作的截止时间为 5 秒；加入后必须在 8 秒内收到完整快照。
客户端在初始快照后发送 ping，此后每 5 秒发送一次，并要求在 4 秒内收到匹配 pong。
这些限制描述示例行为，不代表全面的恶意客户端防护。

协议承载目标提议与权威快照，不承载预测或绘制状态。
仅显示层平滑、原始服务端位置标记，以及实时计数与 RTT 面板见 [网络与数据流程](data-sync_CN.md)。
