# 访客房间协议 v2

**ARK2** 客户端必须与匹配的 ark `guest_room` 服务端一同更新。ARK1 对端会被明确拒绝。
已有 ark 默认 CS/SS 消息头保持不变；本示例在原始 TCP 上显式选择独立消息头。
[共享协议向量](../tests/fixtures/wire-vectors.json) 包含动作、完整属性快照和关联业务拒绝。

| 偏移量 | 字节数 | 内容 |
| --- | --- | --- |
| 0 | 4 | ASCII `ARK2`，协议与版本标记 |
| 4 | 2 | 消息 ID，无符号大端整数 |
| 6 | 2 | 标志，无符号大端整数，必须为零 |
| 8 | 4 | 正文字节数，无符号大端整数，不含消息头，最多 8192 |

正文为 UTF-8 JSON 对象。无效标记、非零标志或过大长度在业务分发前关闭会话。
接收端保留不完整帧、解析合并到达的多个帧，并在重连时清空缓冲区。
编解码器最多保留一个不完整的 8204 字节帧。扩大后的正文限制用于容纳包含转义名字和属性的
16 人快照；ARK1 的上限为 4096。空正文向量仅验证帧格式，不代表有效房间 JSON。

| ID | 方向 | 正文 |
| --- | --- | --- |
| 60000 | 客户端 → 服务端 | `{"name":"Alice","room":"lobby"}` |
| 60001 | 服务端 → 新成员 | `{"player_id":"1","name":"Alice","room":"lobby","width":960,"height":540}` |
| 60002 | 客户端 → 服务端 | `{"seq":1,"x":120,"y":100}` |
| 60003 | 服务端 → 房间成员 | `{"room":"lobby","players":[{"id":"1","name":"Alice","x":120,"y":100,"seq":1,"hp":85,"mp":100,"hp_max":100,"mp_max":100,"action_seq":1}]}` |
| 60004 | 服务端 → 客户端 | `{"code":"invalid_message","message":"reason"}`；动作拒绝还包含 `"action_seq":1` |
| 60005 | 客户端 → 服务端 | `{"nonce":1}` |
| 60006 | 服务端 → 客户端 | `{"nonce":1}` |
| 60008 | 客户端 → 服务端 | `{"seq":1,"kind":"damage"}`；kind 为 `damage`、`skill` 或 `rest` |

60007 不属于动作请求。不要使用 ark Net 保留的 ID 1 和 65535。
唯一 lobby 最多容纳 16 名玩家。名字非空，最多 64 个 UTF-8 编码字节，且不含控制字符。
ID 是临时不透明字符串，不是凭据。坐标为有限值，分别位于 `0..960` 和 `0..540`。
初始位置由服务端决定。移动 `seq` 与动作 `seq` 是独立的 uint32 计数器，分别从 1 开始严格递增。
`nonce` 为 uint32。

每名玩家的快照必须包含 uint32 类型的 `hp`、`mp`、`hp_max`、`mp_max` 和 `action_seq`。
上限必须为正数，当前值不能超过上限。同一玩家的确认移动 `seq` 与 `action_seq` 都不能回退。
新玩家的 HP、MP 及其上限均为 100，动作序列号为 0。

动作仅作用于请求者自己的实体。请求必须且只能包含 `seq` 与 `kind`，不接受客户端提供的数值、目标或属性值。

| 动作 | 服务端拥有的结果 |
| --- | --- |
| `damage` | 自己的 HP 减少 15，下限为零 |
| `skill` | 自己的 MP 减少 20；不足时拒绝 |
| `rest` | 自己的 HP 与 MP 分别增加 20，并限制到各自上限 |

接受动作时推进 `action_seq` 并广播完整快照，即使上限裁剪后属性没有变化。
本示例中 HP 为零仍允许移动。不包含 PvP、物品栏或客户端直接写属性。

客户端最多保留一个待确认动作。只有自己有效快照中的 `action_seq >= pending.seq` 才能确认它；
仅移动更新的快照不能提前确认动作。动作错误回传请求的 `action_seq`；0 表示请求序列号缺失或无效，不能关联有效待确认动作。
精确匹配的拒绝清除对应请求，显示非致命反馈并保留房间连接。不匹配的错误不会清除其他请求。
拒绝不改变属性。其他致命加入错误及协议错误的处理保持不变。

重新加入会清空提议、两套序列号生成器、待确认动作、反馈与不完整帧，绝不重试旧动作。
不恢复旧会话身份或状态。成功加入时先返回接受消息，再发完整快照；加入、接受移动或动作以及断线都会触发快照。

客户端每秒最多发送 10 次移动请求。传输层最多保留 64 个接收事件及一个待完成的本地发送。
连接与发送截止时间为 5 秒；初始快照截止时间为 8 秒。初始快照后发送 ping，此后每 5 秒一次，
要求在 4 秒内收到匹配 pong。这些是示例限制，不代表全面的恶意客户端防护。

显示层平滑、确认后的 HP/MP 条、视觉反馈和应用 RTT 与计数定义见 [数据流程](data-sync_CN.md)。
